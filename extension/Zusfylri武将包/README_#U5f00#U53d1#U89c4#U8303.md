# 无名杀武将拓展包标准工程模板

## 目标

这份模板用于指导一个**长期维护、支持联机、可扩展到 100+ 武将**的无名杀拓展包工程。

设计目标：

1. 新增武将成本低
2. 技能写法统一
3. 联机风险可控
4. 便于调试、回滚、审计
5. 保留向旧结构兼容的过渡空间

## 二、工程分层原则

### 1. core 层

只放**通用能力**，不能写具体武将逻辑。

例如：

* 随机
* storage 同步
* 数组安全写入
* debug 日志
* 常见判定函数

### 2. module 层

一名武将一个文件，放：

* 武将数据
* 技能定义
* 翻译
* 可选：动态翻译

### 3. character 汇总层

把 `module/*.js` 导出的内容整合成：

* `character`
* `skill`
* `translate`
* `characterSort`

### 4. main 层

负责：

* 扩展加载
* 角色包注册
* 初始化时挂载工具/配置

### 5. legacy 层

只用于旧项目迁移，后续逐步清空。

## 三、推荐的角色包注册方式

### `extension.js`

职责：

* 只负责挂载入口
* 不直接塞大量业务逻辑

推荐结构：

```js
import { precontent } from "./main/precontent.js";
import { content } from "./main/content.js";

const EXT_NAME = "你的扩展名";

export default {
    name: EXT_NAME,
    editable: true,
    connect: true,
    precontent,
    content,
};
```

### `main/precontent.js`

职责：

* 提前注册角色包
* 提前加载 core 工具

推荐结构：

```js
import "../core/rng.js";
import "../core/sync.js";
import "../character/index.js";

export function precontent(config, pack) {
    lib.translate.your_extension_character_config = "你的扩展包";
}
```

### `character/index.js`

职责：

* 明确注册为角色包
* 打开联机开关 `connect: true`

推荐结构：

```js
game.import("character", function () {
    return {
        name: "your_extension",
        connect: true,
        character: {},
        skill: {},
        translate: {},
        characterSort: {},
    };
});
```

## 六、RNG 工具模板

文件：`core/rng.js`

```js
(function () {
    if (window.RNG) return;

    window.RNG = {
        random(num) {
            return game.random(num);
        },
        randomGet(list) {
            if (!Array.isArray(list) || !list.length) return undefined;
            return list[game.random(list.length)];
        },
        randomGets(list, count) {
            if (!Array.isArray(list) || !list.length || count <= 0) return [];
            const copy = list.slice();
            const result = [];
            while (copy.length && result.length < count) {
                const index = game.random(copy.length);
                result.push(copy.splice(index, 1)[0]);
            }
            return result;
        },
    };
})();
```

### RNG 规范

允许：

* `RNG.random(...)`
* `RNG.randomGet(...)`
* `game.random(...)`

禁止：

* `Math.random()`

## 七、Sync 工具模板

文件：`core/sync.js`

```js
(function () {
    if (window.Sync) return;

    window.Sync = {
        setStorage(player, key, value) {
            player.storage[key] = value;
            player.syncStorage(key);
            return value;
        },
        deleteStorage(player, key) {
            delete player.storage[key];
            player.syncStorage(key);
        },
        ensureArray(player, key) {
            if (!Array.isArray(player.storage[key])) {
                player.storage[key] = [];
                player.syncStorage(key);
            }
            return player.storage[key];
        },
        pushUnique(player, key, value) {
            const list = this.ensureArray(player, key);
            if (!list.includes(value)) {
                list.push(value);
                player.syncStorage(key);
            }
            return list;
        },
        removeValue(player, key, value) {
            const list = this.ensureArray(player, key);
            const index = list.indexOf(value);
            if (index !== -1) {
                list.splice(index, 1);
                player.syncStorage(key);
            }
            return list;
        },
        addNumber(player, key, delta) {
            const value = (player.storage[key] || 0) + delta;
            player.storage[key] = value;
            player.syncStorage(key);
            return value;
        },
    };
})();
```

### Sync 规范

允许：

* `Sync.setStorage(...)`
* `Sync.deleteStorage(...)`
* `Sync.pushUnique(...)`

不推荐：

* 直接 `player.storage.xxx = ...` 后忘记 `syncStorage`

## 八、技能编写标准

### 标准 1：优先使用官方行为函数

优先使用：

* `player.draw()`
* `player.gain()`
* `player.lose()`
* `player.loseToDiscardpile()`
* `player.damage()`
* `player.recover()`

不要优先使用：

* DOM 操作
* `ui.discardPile.appendChild(...)`
* 手动塞手牌节点

### 标准 2：复杂技能统一使用 step 或 async

推荐：

```js
content: function () {
    "step 0";
    ...
    "step 1";
    ...
}
```

或：

```js
async content(event, trigger, player) {
    ...
}
```

### 标准 3：filter 只做判断，不做副作用

`filter` 中禁止：

* 改 storage
* 摸牌
* 失牌
* 随机
* 任何界面操作

### 标准 4：联机禁止项

禁止：

* `Math.random()`
* `setTimeout()`
* `Date.now()` / `new Date()`
* `if (player == game.me) { ...规则逻辑... }`
* 直接 DOM 改游戏状态

### 标准 5：涉及 storage 必须统一封装

例如：

```js
Sync.setStorage(player, "zus_mark", 1);
Sync.pushUnique(player, "zus_targets", target);
```

## 十、调试规范

### 1. 每次大改都打版本标签

建议：

* `v1_baseline`
* `v2_connect_register`
* `v3_core_layer`
* `v4_skill_rewrite`

### 2. 新技能先单机测，再联机测

测试顺序：

1. 是否能进入选将列表
2. 单机是否触发
3. 联机是否触发
4. 联机是否不同步
5. 是否有误触发

### 3. 一次只改一个问题

不要同时：

* 改 trigger
  n- 改 storage
* 改事件内容
* 改目录结构

否则很难 debug。

## 十一、推荐开发流程

### 新增武将流程

1. 新建 `module/xxx.js`
2. 写 `character / skill / translate`
3. 在 `character/*.js` 汇总层接入
4. 放图片和音频
5. 单机测试
6. 联机测试
7. 写入 `CHANGELOG`

### 修改旧武将流程

1. 先复制旧技能
2. 只改一项逻辑
3. 保留原版注释
4. 补联机测试记录

## 十四、最终原则

1. **规则层优先，UI 层靠后**
2. **标准事件优先，手搓流程靠后**
3. **同步安全优先，效果炫技靠后**
4. **先能调试，再谈优雅**
5. **所有新武将都按模板走，不再自由发挥工程结构**

---

## 十五、给未来开发者的一句话

写无名杀扩展时，不要先问“我怎么实现效果”。

先问三件事：

1. 这个效果属于哪个标准事件链？
2. 能不能用 `player.xxx()` / `game.xxx()` 实现？
3. 联机下这一步会不会不同步？

只要先按这三问写，项目就会越来越稳。
