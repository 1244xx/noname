## 一、技能定义与配置

### 1.1 viewAs 技能的完整配置

| 属性 | 作用 | 缺失的后果 |
|------|------|-----------|
| `enable: ["chooseToRespond", "chooseToUse"]` | 声明哪些场景可触发 | 技能不出现候选列表 |
| `viewAs(cards, player)` | 函数形式，定义视为的牌 | 核心定义（*不能是静态对象*） |
| `filterCard(card)` | 筛选可用牌 | 无法过滤牌类型 |
| `viewAsFilter(player)` | 是否有可用牌 | 技能图标常亮/常灰 |
| `position: "hes"` | 可选牌的区域 | 默认只有手牌区 |
| `check(card)` | AI 选牌评分 | AI 无法正确选牌 |
| `prompt` | 技能提示文字 | 无提示 |
| `ai.respondShan` / `ai.respondSha` | AI 知道能当闪/杀 | AI 不出闪/杀 |

关键发现：
- `position: "hs"` = 手牌区 + 特殊区，**不含装备区**
- `position: "hes"` = 手牌区 + 装备区 + 特殊区
- **`viewAs` 必须写为函数** `viewAs(cards, player) { return { name: "sha" }; }`，静态对象 `viewAs: { name: "sha" }` 在 `chooseToUse`/`chooseToRespond` 场景下无效
- **`viewAs` 技能的 `content` 不会被执行**，限制次数直接用 `round: 1` 或 `usable: 1`，框架自动处理

### 1.2 `filterCard: false` 不等于"拒绝所有牌"

```js
// ❌ 布尔值 false 被框架解释为"不过滤"→ 所有牌通过
filterCard: false,
selectCard: -1,  // 全选 → 所有手牌被消耗！

// ✅ 必须写成函数
filterCard() {
    return false;
},
```

### 1.3 `round: 1` 与 `usable: 1` 的选择

| 属性 | 含义 | 重置时机 | 适用场景 |
|------|------|----------|----------|
| `round: 1` | 每轮限一次 | `roundStart` | 全局节奏控制 |
| `usable: 1` | 每回合限一次 | 每个角色回合开始时 | 与回合相关的触发 |

多功能的技能不能在父技能上加 `round`/`usable`，必须拆子技能后各自加限制：
```js
mainSkill: {
    group: ["mainSkill_draw"],
    async content() { /* 追踪 X 值、维护状态 */ }
},
subSkill: {
    mainSkill_draw: {
        usable: 1,
        priority: -1,  // 确保父技能先执行
        async content() { /* 摸牌 */ }
    },
}
```

### 1.4 多效果共用状态的设计模式

每轮各可发动一次的三个子效果，共用父技能标记展示状态：

```js
parentSkill: {
    mark: true,
    intro: {
        content(storage, player) {
            return [
                player.storage.sub1_round ? "已发动" : "可发动",
                player.storage.sub2_round ? "已发动" : "可发动",
            ].join("/");
        },
    },
    group: ["sub1", "sub2", "reset"],
},
reset: {
    trigger: { global: "roundStart" },
    silent: true,  // 不弹窗、不日志
    content() {
        delete this.player.storage.sub1_round;  // 注意：非 async 用 this.player
        delete this.player.storage.sub2_round;
    },
},
sub1: {
    filter(event, player) {
        return !player.storage.sub1_round;  // 本轮未发动
    },
    async content(event, trigger, player) {
        player.storage.sub1_round = true;
        // ...
    },
},
```

**`round: 1` 只能用在简单技能上。多效果共享状态、viewAs 等复杂场景，改为手动 storage 标记 + 复位子技能模式。**

### 1.5 `chooseXXX` 的取消支持

```js
// 强制选择（锁定技效果，不可跳过）
player.chooseCard("h", true, "请选择一张牌")

// 可选选择（主动技效果，允许取消）
player.chooseCard("h", "请选择一张牌（可取消）")
```

### 1.6 `frequent` + 内部强制 = "可跳过但发动后不可反悔"

`forced` = 锁定技（无法取消、可被屏蔽），不是"强制操作"的意思。
```js
// ✅ 正确：frequent（可跳过）+ 内部 true（发动后强制选牌）
skill: {
    frequent: true,
    async cost(event, trigger, player) {
        const result = await player.chooseToDiscard("h", true, "请弃置一张牌").forResult();
        // true → 点了发动就必须弃牌，无取消按钮
    },
}
```

## 二、触发与事件

### 2.1 filter 中不要调用 `canUse` / `inRange`

`filter` 在触发编排阶段执行，距离计算链中某些玩家引用可能为 `undefined`，调用 `canUse()` 会导致空引用崩溃。

| 阶段 | 可做什么 | 不可做什么 |
|------|----------|------------|
| `filter` | 轻量判断（牌名、手牌数、标记等）| `canUse()`、`inRange()`、距离相关 |
| `cost` | 完整判断（`canUse`、`chooseXXX`）| — |

### 2.2 触发时机名 vs 事件名：用框架传入的第三参数

多时机触发的技能中，`trigger.name` / `event.name` **不等于触发时机名**：
```js
trigger: { player: "useCard", source: "damageBegin3" },

// ❌ 错误
filter(event, player) {
    if (event.name === "damageBegin3") ...  // false! event.name 是 "damage"
}

// ✅ 正确：用 filter 的第三个参数
filter(event, player, name) {
    if (name === "damageBegin3") ...  // name 是框架传入的 triggername
}
async content(event, trigger, player) {
    if (event.triggername === "damageBegin3") ...  // content 中用 event.triggername
}
```

### 2.3 子事件缺少父事件属性（`trigger` 层级）

子事件触发时机（如 `useCardToBefore`），`trigger` 是子事件对象，没有父事件才有的属性（如 `directHit`）：
```js
// ❌ directHit 挂在父事件 useCard 上
trigger.directHit  // undefined

// ✅ 取父事件
trigger.getParent().directHit
```

**存储 trigger 到 storage 供后续使用时，先确认需要的属性在哪个事件层级。子事件时机 → 优先 `trigger.getParent()`。**

### 2.4 回合内触发的技能需防回合外误触发

`trigger: { player: "useCardAfter" }` 在回合外打闪、吃桃时也会触发。filter 第一条必须是：
```js
filter(event, player) {
    if (_status.currentPhase !== player) return false;  // 仅自己回合内
    // ...
}
```

### 2.5 `insertPhase` 在 `phaseAfter` 时机失效

`insertPhase` 把额外回合插入父级 phase 的 `next` 链。`phaseAfter` 触发时父级已执行完毕，不再处理 next 链。回合结束后必须用独立事件：
```js
// ✅ 回合结束后用独立 phase 事件
trigger: { player: "phaseAfter" },
async content(event, trigger, player) {
    await player.phase("skillName");  // 独立事件，立即执行
}
```

### 2.6 `chooseToRespondBegin` 中 `parent` 可能为 `undefined`

```js
const parent = trigger.getParent();
if (parent) {  // ✅ 必须判空
    parent.result = { bool: true, card: ..., cards: [] };
}
```

### 2.7 `shaHit` —— 框架唯一的"目标未出闪"权威信号

需要判断"目标是否出闪"时，不要自己追踪 `respond` 或 `excluded`。直接用框架信号：

| 信号 | 含义 |
|------|------|
| `shaHit` | 目标未出闪（与伤害是否造成无关） |
| `shaMiss` | 目标出了闪 |
| `shaDamage` | 杀造成伤害 |
| `shaUnhurt` | 杀未造成伤害 |

```js
club: {
    trigger: { player: "shaHit" },
    async content(event, trigger, player) {
        const target = trigger.target;  // 未出闪的目标
    },
},
```

## 三、cost 与 content 的数据传递

### 3.1 `event.result` 隔离：用 `cost_data` 传值

`cost` 和 `content` 运行在不同事件中，各有独立的 `result`：
```js
async cost(event, trigger, player) {
    const result = await player.chooseControl(...).forResult();
    event.result = {
        bool: result.control !== "cancel2",
        cost_data: { control: result.control },  // ✅ 传递给 content
    };
},
async content(event, trigger, player) {
    const choice = event.cost_data.control;  // ✅ 用 cost_data 读取
}
```

### 3.2 `forResult()` 返回值可能为 `undefined`

边界情况（目标阵亡、牌堆无牌）下 `forResult()` 返回 `undefined`，访问 `.bool` 会崩溃：
```js
const result = await judgeEvent.forResult();
if (result && !result.bool) { ... }  // ✅ 先判空
```

## 四、`directHit` 与 技能禁用

### 4.1 `directHit` 实现"不可响应"的标准模式

临时技能 + `useCardToTargeted` 触发器：
```js
// 出杀前添加
player.addTempSkill("jiba_directHit");
await player.useCard(virtualCard, target, false);

// 临时技能
jiba_directHit: {
    trigger: { player: "useCardToTargeted" },
    forced: true, popup: false, silent: true,
    filter(event, player) {
        return event.card && event.card.name === "sha" && event.card.nature === "fire";
    },
    content(event, trigger, player) {
        trigger.directHit.add(trigger.target);  // directHit 在父事件 useCard 上
        player.removeSkill("jiba_directHit");
    },
},
```

### 4.2 `skillBlocker` 替代 `removeSkill` —— 临时禁用技能的正确方式

`removeSkill` 会触发 `onremove`，破坏标记、storage 和累计数据。用 `skillBlocker` 静默阻断：

```js
club_silent: {
    init(player, skill) {
        player.addSkillBlocker(skill);
    },
    onremove(player, skill) {
        player.removeSkillBlocker(skill);
    },
    skillBlocker(skill, player) {
        const info = get.info(skill);
        if (!info) return false;
        if (info.locked || info.forced || info.juexingji) return false;
        return true;  // 拦截所有非锁定/非强制/非觉醒技
    },
    trigger: { player: ["phaseAfter", "dieBegin"] },
    forced: true, popup: false,
    content() {
        player.removeSkill("shazhang_club_silent");
    },
},
```

**不破坏技能状态，不触发 `onremove`，不需要恢复逻辑。** 框架的 `fengyin`/`baiban` 就是最佳实践。

### 4.3 子技能 `group` 的生效层级

subskill 通过 `group` 引用另一个 subskill 时，激活链需从根技能完整追溯。有断裂则不激活。复杂引用链时直接把功能内联到父技能中。

## 五、AI 相关

> AI 审计的完整方法论、检查清单、问题模式见 [`AI审计经验.md`](./AI审计经验.md)。

### 5.1 `ai.result` 静态正值 = 无限循环

```js
// ❌ AI 每次扫描看到正值 2，反复发动直到资源耗尽
ai: { result: { player: 2 } }

// ✅ 有消耗的技能必须动态判断
ai: {
    result: {
        player(player) {
            if (player.countCards("h") <= 2) return 0;
            return 1;
        },
    },
},
```

### 5.2 `chooseToDisable` AI 回调签名

三个参数 `(event, player, list)`，**第三个参数 `list` 才是可选列表**，不是 `event._controls`：
```js
.set("ai", function (event, player, list) {
    if (list.includes("equip2")) return "equip2";
    return list.randomGet();
})
```

### 5.3 调用不存在的 Player API

无名杀 Player 类的方法清单：
- `player.isDamaged()` ✅ — 判断负伤（hp < maxHp）
- `player.isDying()` ✅ — 判断濒死
- `player.isMaxHp()` ✅ — 判断体力上限最大
- `player.needsToRecover()` ❌ — **不存在！**
- `player.needsHeal()` ❌ — **不存在！**

## 六、mod 与 框架机制

### 6.1 手牌上限 + 弃牌保护 = 真正的"不计入上限"

```js
mod: {
    ignoredHandcard(card, player) {
        if (get.type(card, "trick") === "trick") return true;  // 不占上限
    },
    cardDiscardable(card, player, name) {
        if (name === "phaseDiscard" && get.type(card, "trick") === "trick") return false;  // 不可弃
    },
}
```
两者缺一不可。只写 `ignoredHandcard`，弃牌阶段仍可弃锦囊牌保留基本牌。

### 6.2 `targetEnabled` vs `playerEnabled`

| mod 名 | 查出谁 | 适用场景 |
|--------|--------|----------|
| `playerEnabled` | 出牌人 | 限制自己的出牌行为 |
| `targetEnabled` | 目标 | 限制他人以你为目标 |

### 6.3 `cardRecastable` mod —— 扩展框架重铸按钮

让特定牌进入框架内置重铸按钮，用 mod 而非创建独立技能：
```js
mod: {
    cardRecastable(card, player) {
        const info = get.info(card);
        if (info && info.type === "equip" && info.subtype === "equip1") return true;
    },
},
```

重铸的 `filterCard` 不应依赖 `cardEnabled`（语义多变），直接按设计意图过滤。

## 七、数据与状态管理

### 7.1 数据格式兼容性：对象 vs 数组

无名杀原生武将用数组格式 `info[3]` 访问技能列表，哈包用对象格式 `info.skills`。`player.reinit()` 内部用 `info[3]` 读写技能 → 对象格式的武将技能替换**静默跳过**。

**任何调用 `reinit` 涉及对象格式角色时，必须手动处理技能替换：**
```js
const oldInfo = lib.character[oldName];
if (oldInfo?.skills) {
    for (const s of oldInfo.skills) target.removeSkill(s);
}
await target.reinit(oldName, newChar, null, true);
if (newInfo.skills) {
    for (const s of newInfo.skills) target.addSkill(s);
}
```

### 7.2 概率模型设计：按张数加权 vs 按牌名等概率

"随机获得一种锦囊牌"的实现确认：
- 按张数加权：`get.cardPile(c => get.type(c) === "trick", "random")`
- 按牌名等概率：先 `lib.inpile` 随机取牌名，再按名抽牌

**两者概率分布完全不同，必须先和设计者确认。**

### 7.3 废除/重来类递归需固定目标

递归重来时对手必须不变：
```js
async function executeSkill(initiator, depth, fixedTarget = null) {
    if (!fixedTarget) target = await initiator.chooseTarget(...).forResult();
    else target = fixedTarget;
    // ... 废除时传入原对手
    await executeSkill(vetoer, depth + 1, opponent);
}
```

### 7.4 父技能与子技能的层级交换

父技能应有可见交互行为（对话框、日志），被动生效逻辑放在 `silent` 子技能中。若子技能比父技能更"活跃"，考虑交换层级。

### 7.5 `targets` 过滤排除自己时确认自身是否需要

```js
// ❌ 自己被排除了
const targets = game.filterPlayer(target => target.isIn() && target !== player);
for (const t of targets) t.addSkills("jibao");
// 觉醒者自己没拿到！

// ✅ 先给自己加
if (!player.hasSkill("jibao")) player.addSkills("jibao");
```

### 7.6 `await` 与链式调用的优先级陷阱

`await player.addToExpansion(card, "gain2").gaintag.add("yinqing")` → `await` 等的是 `.add("yinqing")` 返回值，异步操作未完成就返回了。
```js
// ✅ 三步走：创建 → 配置 → await
const next = player.addToExpansion(result.card, "gain2");
next.gaintag.add("yinqing");  // 在 await 之前设属性
await next;
```

### 7.7 `lib.card[name]` 自定义属性不复制到 Card DOM

`lib.card[name]` 上的非标准属性（如 `yiti`、`cardcolor`）不会拷贝到 Card DOM。必须通过 `get.info(card)` 或 `lib.card[card.name]` 访问。
`get.info({ name })` 也**不返回自定义属性**，只含标准属性描述符。

### 7.8 `disableEquip` 缺少 `await` 导致标记丢失

`disableEquip` 创建的是延迟事件，后续 `markSkill` 加的标记会被延迟的 UI 刷新清掉：
```js
await player.disableEquip(3);  // ✅ 先废完
player.markSkill("_yiti_mark");  // ✅ 再打标记
```

### 7.9 `equipSkill: true` 不适用于义体技能

`equipSkill` 在卡牌离开装备区时自动移除技能。义体卡根本不在装备区上，通过 `addAdditionalSkill` 手动管理，不能加 `equipSkill`。

### 7.10 `addAdditionalSkill` 第三个参数 `keep=true`

`addAdditionalSkill(key, skills, keep)` 在 `keep` 为 false（默认）时**先清空该分组所有旧技能**再添加。循环调用只留最后一个：
```js
// ✅ 方式一：一次性传数组
addAdditionalSkill("_yiti_mark", skills);
// ✅ 方式二：keep=true 追加
addAdditionalSkill("_yiti_mark", skill, true);
```

### 7.11 坐骑 — `hasEnabledSlot("horse")` + `chooseToDisable(true)`

坐骑栏是合并概念。`chooseToDisable(true)` 返回的 control 是 `"equip3_4"`，同时废 3 号和 4 号栏。

### 7.12 `judge().forResult()` 不返回卡牌

返回的是 `{ bool }` 不是 `{ card }`。需要判定牌数据时通过 `judge(callback)` 闭包捕获：
```js
let num;
await player.judge(card => { num = get.number(card); return 0; }).forResult();
```

### 7.13 判定系统替代手动翻牌

需要翻牌展示给所有玩家的场景，用 `player.judge()` 而非手动 `get.cards()` + 弃牌。一步完成翻牌、展示、弃牌全流程。

## 八、lib 全局 API

### 8.1 `lib.skill.global` 的 API

`lib.skill.global` 是类数组对象，API：`.add()` / `.remove()` / `.includes()`。**没有 `.has()` 方法**。

### 8.2 `lib.characterPack` 无条件加载

引擎每局从 `lib.characterPack` 无条件遍历加载角色，即使 `config.characters` 中未勾选也会加载。关闭武将包必须同时管理两处：
```js
if (lib.config.characters.includes(PACK_NAME)) {
    lib.characterPack[PACK_NAME] = allCharacters;
    Object.assign(lib.character, allCharacters);
}
```

## 九、Git 与 项目管理

### 9.1 PowerShell 终端

- 链式命令用 `;` 而非 `&&`（`&&` 不是有效分隔符）
- 多行 commit message 用多个 `-m`：`git commit -m "line1" -m "line2"`
- 不支持 heredoc（`cat <<'EOF'`）

### 9.2 多层级 `.gitignore`

- `apps/core/.gitignore` → `extension/**` 屏蔽所有扩展，`!extension/哈包/**` 排除
- `packages/extension/.gitignore` → `*/` 只影响那个目录，和 `apps/core/extension/` 无关
- 扩展目录新文件默认被忽略，首次提交务必 `git add -f`

### 9.3 IDE 未追踪文件不可见

IDE 面板默认不显示 `.gitignore` 排除的文件。必须用命令确认：
```bash
git ls-files -- "path/"
git ls-files --others --exclude-standard
```
图片等二进制文件更容易被忽略。

### 9.4 牌堆条目残留

`lib.card.list` 是持久化全局牌堆，扩展 push 的条目在包关闭后不自动消失。每次 precontent 开头先清理再按配置加回。

## 十、变量命名与基础规范

### 10.1 变量命名一致性

```js
// ❌ 赋值给 targetResult，判断时写了 result
const targetResult = await player.chooseTarget(...).forResult();
if (!result.bool || ...)  // ReferenceError: result is not defined
```

**`.forResult()` 返回值立即赋给命名一致的变量，下一行立即校验。**

### 10.2 `chooseToUse`/`chooseToRespond` 必须有可选实体牌

`enable: ["chooseToUse", "chooseToRespond"]` 强制要求从手牌/装备区选至少一张实体牌。代价不是选牌的技能应改用：

| 场景 | 方案 |
|------|------|
| 主动使用 | `enable: "phaseUse"` + `content` 中 `player.useCard(virtualCard, target)` |
